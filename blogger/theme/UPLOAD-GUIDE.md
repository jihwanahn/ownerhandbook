## 1단계 — 현재 테마 백업 (30초, 되돌리기용)

1. blogspot 관리 화면에서 왼쪽 메뉴 **테마** 클릭
2. 테마 미리보기 오른쪽 위의 **점 3개(⋮)** → **백업/복원** 클릭
3. **백업** 버튼 → 지금 쓰는 테마 XML이 다운로드됩니다 (파일명 예: `theme-….xml`)
4. 이 파일을 `jhl-secrets` 옆이 아니라 **바탕화면 등 찾기 쉬운 곳**에 그대로 두세요.
   문제가 생기면 이 파일을 그대로 다시 업로드하면 원상복구됩니다.

## 2단계 — 새 테마 업로드 (1분)

1. 같은 **백업/복원** 창에서 **업로드** 클릭
2. `E:\ownerhandbook\blogger\theme\owners-handbook-v3-decl.xml` 선택 → **업로드**
3. Blogger가 테마 검증을 통과하면 화면에 새 테마 미리보기가 나타납니다.
   - 실패 메시지가 뜨면 **업로드하지 마시고** 그 메시지를 그대로 알려주세요.
     (검증에서 막힌 항목을 바로 고치겠습니다. 1단계 백업으로 되돌리면 아무 영향 없습니다.)
   - **'테마를 복원할 수 없습니다'로 거부되면 아래 2-대안(수동 적용)으로 진행하세요.**
     (선언 세대를 맞춘 새 파일이라 이번에는 통과할 수도 있습니다.)
4. **저장** 클릭 → 적용 완료

## 2-대안 — '테마를 복원할 수 없습니다'로 업로드가 거부될 때 (수동 적용, 약 3분)

백업/복원 업로드가 제3자 테마 파일을 거부하는 것은 Blogger에서 알려진 문제입니다.
아래 수동 방법이 표준 우회 절차이고, 중간에 실패해도 현재 테마는 그대로 유지되므로 안전합니다.
(**2026-10-16 이 방법으로 적용에 성공했습니다** — 결과는 라이브 페이지에서 검증 완료.)
(테마 파일 자체는 검증을 통과한 정상 파일입니다 — 문제는 업로드 경로 쪽입니다.)

1. **백업 확인** — 1단계의 백업 파일이 없다면 먼저 `백업 → 다운로드`로 현재 테마를 저장(되돌리기 보험)
2. **HTML 편집 열기** — 테마 → 맞춤설정 옆 **▼(또는 ⋮ '더보기')** → **'HTML 편집'**(표기: 'HTML 수정')
3. **기존 코드 임시 보관** — 편집창 클릭 → **Ctrl+A → Ctrl+C** → 메모장에 붙여두기
4. **기존 코드 삭제** — 편집창에서 **Ctrl+A → Delete**
5. **새 테마 붙여넣기** — `owners-handbook-v3-decl.xml`을 **메모장**으로 열어 **Ctrl+A → Ctrl+C** → 편집창에 **Ctrl+V**
   (파일 **전체**를 그대로 — 첫 줄 `<?xml ...?>` 포함 — 붙여넣습니다)
6. **저장** — 오른쪽 위 저장 아이콘(플로피)
7. **실패 문구가 뜨면** — 저장되지 않고 기존 테마가 유지됩니다. 문구를 **그대로** 알려주세요.

되돌리기: 1단계 백업 파일을 백업/복원 → 업로드로 올리거나, 3번에서 복사해 둔 기존 코드를
같은 방식으로 다시 붙여넣고 저장합니다. (`owners-handbook-v1.xml`을 붙여넣어도 지금과 같은 결과입니다.)

## 3단계 — 적용 확인 (30초)

1. **테마 → 맞춤설정(연필 아이콘) → 미리보기**에서 상단에 블로그 제목과
   `Home / About / Contact …` 메뉴가 보이는지 확인
2. 스마트폰 미리보기(상단 기기 아이콘)에서 좌우 스크롤이 생기지 않는지 확인
3. 블로그 주소를 새 탭에서 열어 이전 테마와 달라졌는지 확인
4. 확인하셨으면 알려주세요 — 저희가 명령 한 줄로 실제 적용 여부와 SEO 태그를
   검증합니다 (`python blogger/theme/verify_applied.py`, 결과: 테마 마커 4종 +
   og:image·twitter card·JSON-LD·canonical 1개·title 1개 + **위젯 렌더 여부**).
   눈으로 보는 대신 로그로 남깁니다.

## 테마 파일 네 가지 (언제 무엇을 올리나)

| 파일 | 무엇 | 언제 |
| --- | --- | --- |
| `owners-handbook-v3-decl.xml` | **지금 올릴 파일.** v2-decl + `b:layoutsVersion='3'` + `<b:defaultmarkups>` (선언 표면만, 데이터 태그는 v2 유지) | 2단계·2-대안 |
| `owners-handbook-v3-tags.xml` | v3-decl + 데이터 태그까지 v3 모델로 전환 | v3-decl이 저장은 되는데 위젯이 여전히 비거나, Blogger가 데이터 태그를 지적할 때 |
| `owners-handbook-v2-decl.xml` | 선언 메타데이터만 현대 세대 (v3 표면 없음) — 이전에 쓰신 파일 | 문제 생겨 되돌릴 때 |
| `owners-handbook-v1.xml` | 지금 블로그에 올라가 있는 파일 그대로 (**되돌리기용**) | 문제가 생겼을 때 복귀 |
| `bisect/B0-probe.xml` | 디자인 없는 진단용 최소 테마 (섹션 4·위젯 5, 마커 포함) | 위젯이 계속 안 보일 때 (3번) |

파일들은 모두 같은 원본에서 파생됩니다 — `python blogger/theme/decl_variant.py --check`와
`python blogger/theme/v3_variant.py --check`가 "선언/데이터 태그 외에 달라진 것이 없다"를
매번 기계적으로 확인합니다(테스트에 포함).

### 이번 파일에서 바뀐 것 (v2-decl → v3-decl, 선언만)

- `<html>`: `b:layoutsVersion='3'` 추가 (`b:version='2'`·`b:defaultwidgetversion='2'`·
  `class='v2'`·`b:responsive='true'` 유지)
- `<head>`에 `<b:defaultmarkups>` 추가 — 위젯 타입 17종 선언(내용은 **비어 있음**).
  정상 렌더되는 서드파티 테마(vtrick)도 17개 중 16개가 빈 태그입니다.
  우리 테마는 모든 위젯이 자기 includable을 직접 갖고 있어 내용이 필요 없습니다.
- 그 외(CSS·includable·데이터 태그·광고 자리·위젯 설정) **바이트 단위 동일**

이전에 반영된 것: 위젯 선언 세대(`version='2' visible='true'`, 섹션 `name=`), 모바일에서도 이 테마가
쓰이게 하는 세대 선언 3개, 공유 이미지 주소를 블로그 설정값에서 생성, 사이드바·푸터에서 블로그 이름 제거.

## 3-대안 — 진단 테마 (`bisect/B0-probe.xml`, 약 3분, 위젯이 계속 안 보일 때)

디자인이 전혀 없는 **진단용** 파일입니다(노란 안내 문구가 보이는 게 정상). 목적은
**"테마 파일 문제인지, 블로그 레이아웃 문제인지"** 를 가르는 것입니다.

1. 테마 → ⋯ → **HTML 편집** → **Ctrl+A → Delete** → `B0-probe.xml`을 메모장으로 열어
   Ctrl+A → Ctrl+C → 편집창 **Ctrl+V** → **저장**
2. 블로그를 **Ctrl+F5**로 새로 열고, 보이는 문구를 **그대로** 알려주세요 (또는 저희가
   `python blogger/theme/verify_applied.py --bisect` 한 줄로 자동 판정합니다):
   - `B0-MARKER-WIDGET-RENDERED` → 이 블로그는 붙여넣은 테마의 위젯을 **정상 렌더**합니다
   - `B0-EXISTING-ID-WIDGET-RENDERED` → 레이아웃이 이미 아는 위젯 id도 렌더됩니다
   - `B0-PROBE-FRESH-WIDGET-RENDERED`/`B0-PROBE-FRESH-CONTENT`/`B0-PROBE-BARE-FRESH-CONTENT`
     → 처음 보는 위젯 id까지 새로 만들어집니다
   - **아무것도 안 보임** → 이 블로그는 붙여넣기 경로로는 위젯을 만들지 않습니다(파일 문제 아님)
3. 되돌리기: `owners-handbook-v3-decl.xml`(또는 백업)을 같은 방식으로 다시 붙여넣고 저장.


**테마 → ⋮ → 백업/복원 → 업로드 → 1단계에서 받아둔 백업 XML 선택 → 업로드.**
언제든 이전 상태로 되돌아갑니다.

## 업로드 후 할 일 (테마 설정, 저희가 값 제공 예정)

- **레이아웃 → 섹션 배치**: 업로드하면 페이지/라벨/HTML 위젯이 새 위치로 옮겨집니다.
  - 상단 메뉴: `Pages`(About·Contact·Privacy) + `Categories`(라벨)
  - 오른쪽 사이드바: 소개 글 + 카테고리 목록
  - 푸터: 정책 페이지 링크 + 저작권 문구
  - 레이아웃에 **`BlogSearch1`(검색 상자)** 잔여 인스턴스가 보이면 **삭제**해 주세요 —
    테마에 없는 항목이라 남아 있으면 상단 메뉴 자리를 차지합니다.
  - 위젯이 비어 보이면 **레이아웃 → 해당 섹션의 `+ 위젯 추가`**로 다시 넣으시면 됩니다.
    (페이지 위젯은 About/Contact/Privacy 페이지를 먼저 만든 뒤에 목록이 채워집니다.)
- **광고 자리 3곳은 비어 있는 게 정상입니다.** 상단·본문 뒤·하단에 컨테이너만
  준비해 두었고, AdSense 승인 후(Phase 3) 코드만 넣으면 됩니다.
- **파비콘**: Blogger 설정 → 기본 → 파비콘에서 업로드하시면 테마가 그대로 사용합니다.
- **검색 설명·OG 태그·canonical**은 Blogger가 자동으로 넣고, 이 테마는 중복 생성하지
  않습니다. 글별 검색 설명을 직접 넣고 싶으시면 글 편집 화면 오른쪽 **검색 설명**
  항목에 붙여넣으시면 됩니다(넣지 않으면 본문 요약이 자동 사용됩니다).
- **블로그 언어**: Blogger 설정 → 언어가 **한국어**로 되어 있습니다(빈 목록 문구 등이 한국어로
  나옵니다). 영어 대상 사이트이니 **영어**로 바꾸시는 것을 권합니다.
